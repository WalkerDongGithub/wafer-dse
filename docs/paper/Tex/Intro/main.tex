\chapter{引言}\label{chap:intro}

\section{研究背景与问题}\label{sec:intro-bg}

硅 interposer 与先进封装技术的持续进步，正把晶圆级集成从学术概念推向工业量产。
TSMC 的 InFO-SoW 平台在 Tesla Dojo 训练 Tile 中集成了 25 个 D1 裸片~\cite{tesla2022dojo}；
Cerebras WSE-3 以单晶圆级芯片集成约 90 万个处理核心，2D Mesh 提供 20\,PB/s 的片上聚合带宽~\cite{cerebras2022wse2}。
在此趋势下，一个直接的架构问题是：能否在晶圆上构建一个网络交换机？

晶圆级平台在这一方向上有两项天然优势。
其一，硅 interposer 提供的裸片间互联密度远超传统 PCB——以 $12\times12$\,mm 裸片、45\,$\mu$m pitch 的 $\mu$bump 阵列计算，
单裸片可布置约 7 万个互联点，聚合 IO 带宽可达 Pbps 量级~\cite{ucie2.0-2024}，为超大 radix 交换网络提供了物理基础。
其二，interposer 上的互联协议灵活可配——UCIe Advanced（2.5D）每 bit 功耗低至 0.25\,pJ，
SerDes VSR/MR/LR 覆盖 10\,cm 至 100\,cm 的 reach 范围，光学互联（如 TeraPHY）可提供 8\,Tbps 的单 chiplet 带宽~\cite{oif-cei-5.1}——
设计者可根据裸片间距自适应选择速率与功耗等级。

学术界已对此方向做出响应。Chen 等~\cite{chen2024waferscale}首次量化了晶圆级交换机的 radix 提升潜力，
指出仅面积约束下可达传统芯片级交换机 32 倍的端口密度；
Feng 和 Ma~\cite{feng2024switchless}提出「无交换机 Dragonfly」架构，以晶圆级高密度互联替代传统高 radix 物理交换机；
Wan 等~\cite{wan2024architectural}在 2D Mesh 物理拓扑上叠加 Butterfly Fat-Tree 逻辑拓扑，实现 896 端口、8.96\,Tb/s 的晶圆级交换系统；
Yang 等~\cite{yang2025pd}提出的 TickTock 框架面向 LLM 训练进行物理-逻辑拓扑联合协同设计。
这些工作确立了晶圆级交换机作为独立研究方向的价值，
却也共同揭示了一个尚未被充分解决的核心困难：
晶圆级交换机的设计空间极大，且体系结构决策与多类物理约束之间存在深度耦合。

\section{两个根本困难}\label{sec:intro-difficulties}

\subsection{设计空间组合爆炸}\label{sec:intro-space}

晶圆级交换机需要在拓扑族（Dragonfly、Mesh、Torus、$k$-ary $n$-cube 等）与拓扑参数（Dragonfly 的 $a,p,h$）~\cite{kim2008technology}、
路由策略（Valiant、minimal、自适应）、互连标准（UCIe Advanced/Standard、SerDes VSR/MR/LR、光学互联）~\cite{ucie2.0-2024,oif-cei-5.1}、
裸片规格（面积、峰值功耗、bump pitch）、封装方式与冷却方案等维度上做出联合决策。
这些选择跨越从体系结构到物理实现的多个抽象层次，其笛卡尔积规模远超 $10^6$ 个候选设计点。
在此规模下，cycle-accurate 仿真器单次评估需数分钟量级~\cite{dally2004principles}，完全不可行；
chiplet 设计空间探索工具（如 FPIA~\cite{jiao2024fpia}、RapidChiplet~\cite{iff2025rapidchiplet}、FireLink~\cite{li2025firelink}）
虽能提供快速评估，但各自聚焦于单一物理维度（布局布线或成本建模），缺乏跨层次的联合决策能力。

\subsection{体系结构与物理约束的深度耦合}\label{sec:intro-coupling}

设计空间巨大只是困难的表象，更深层的问题在于体系结构与物理约束之间的闭环耦合。
传统体系结构设计中，性能分析与物理实现可以大致分离——先定微架构与拓扑，再交由物理设计处理布局、供电与散热。
然而在晶圆级交换机中，这一分离不再成立：
拓扑与路由决策决定每条链路上的流量分布，
流量分布决定每条链路需要的物理 lane 数与信号 $\mu$bump 占用~\cite{ucie2.0-2024}，
lane 的 PHY 额定功耗与芯片峰值功耗共同决定裸片总功耗，
功耗的空间分布经热传导决定温度梯度~\cite{mfit2025}，
而电源 bump 需求反过来挤占信号 bump 的可用面积~\cite{electrical-thermal-chiplet2024}——
四个环节构成闭环。任何单一维度的优化都可能被另一维度的约束推翻，
不存在「先检查 A 再检查 B」的序贯验证流程。

现有工具各自处理这一耦合链中的单个环节——性能仿真器处理流量分布、bump 预算工具处理信号完整性、热分析工具处理温度——
但没有工具能在整个耦合链上联立判断综合可行性。

\section{核心洞察：$B^* = f(\text{期待},\ \text{约束})$ 与统一线性规划}\label{sec:intro-insight}

上述两个困难指向同一个缺口：晶圆级交换机缺乏一个早期设计决策工具，
能够在给定技术选型下快速判定候选方案的综合可行性，并给出明确的设计改进方向。

本文的起点是一个结构性的观察。尽管晶圆级交换机涉及的约束数量庞大、物理来源各异，
但把它们归并后，恰可归为\textbf{期待}与\textbf{约束}两侧：

\begin{itemize}
\item \textbf{期待（性能侧）}：在最坏流量模式（排列）下，网络仍具备无阻塞的\textbf{潜能}——
即最优自适应路由下物理资源足以支撑全部指定模式的同时交换。
\item \textbf{约束（物理侧）}：$\mu$bump 预算、布线容量、热（芯片峰值功耗 + PHY 额定功耗）与 C4 出口；
信号完整性经互连标准（UCIe/OIF-CEI 的 lane rate / reach / BER / 功耗档位）内嵌为约束，技术选型必须依赖已有互连标准。
\end{itemize}

关键之处在于二者的数学形态都极其规整。
性能侧可化为关于\textbf{负载包络} $\mathbf{L}$ 的线性等式/不等式
（$|\mathcal{R}|$ 个排列模式的外生需求 + 包络 $\mathbf{L}\ge\mathbf{L}^{(r)}$）；
物理侧的各项约束，在按\textbf{物理位置}组织（on-die / $\mu$bump / 布线 / 热 / C4 / 组间 / die 缩放）后，
也都可写成同一组变量上的线性不等式。
于是，全部约束被统一为单个\textbf{线性规划}：
给定技术选型与端口带宽 $B$，联立判定是否存在一组变量同时满足全部约束；
再对 $B$ 二分，即得\textbf{最大端口无阻塞带宽} $B^*$。

一句话概括本文的框架：
\begin{equation}\label{eq:intro-bstar}
    B^* \;=\; f(\text{期待},\ \text{约束})
\end{equation}
我们在给定期待与约束下「尽我们所能」求最大的端口无阻塞带宽。
由此，\textbf{期待降低}（少要求一些流量模式无阻塞）或\textbf{约束放宽}（工艺、散热、功耗调度改善），$B^*$ 都提高；
灵敏度分析（第~\ref{chap:sensitivity}章）正是把这句话转化为对参数 $\theta$ 的定量梯度 $\partial B^*/\partial\theta$。

\section{本文贡献}\label{sec:intro-contrib}

\begin{enumerate}
\item \textbf{联立可行性判定：统一线性规划框架。}
把按物理位置组织的全部约束统一为同一组变量上的线性不等式组，
将「多轮独立验证」替换为「单次联立判定」，在给定技术选型下一次性判定候选方案的综合可行性；
框架支持按需切换建模精度（如热的粗筛/细粒度），精度升级只替换系数矩阵、不改变框架结构。

\item \textbf{$B^*$ 统一筛选指标。}
以 $B^* = f(\text{期待},\ \text{约束})$ 作为统一的设计点筛选指标：
固定 $B$ 的可行性 LP 配合二分搜索，以对数次 LP 调用求得最大端口无阻塞带宽，
使不同拓扑、不同技术选型的设计点在同一个标量上可比。

\item \textbf{灵敏度分析：从「可行/不可行」到「改哪里、改多少」。}
在二分所得 $B^*$ 处，用事后闭式 $\lambda_j = 1/(A_j\cdot\mathbf{L}^*)$ 提取绑定约束的影子价格，
并借助 Milgrom--Segal 包络定理给出 $B^*$ 对\textbf{约束旋钮}（物理参数）与\textbf{期待旋钮}（$\mathcal{R}$ 集合）的梯度，
归一化后为架构师提供定量的投资优先级（每 +1 $\mu$bump / +1\,W 散热换多少带宽）。
\end{enumerate}
