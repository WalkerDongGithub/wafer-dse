## 0. 论文的核心故事（一句话）

**性能说"我至少需要这么多"，物理说"我最多能给这么多"——可行解夹在两个曲面之间。线性规划找到它们能不能对上。**

这不是一个优化问题。这是一个**对抗游戏的形式化**：最差的流量模式打过来，你用静态的物理配置去接。数学上它是线性规划的可行性判定；叙事上它是体系结构需求和物理极限之间的对话。

## 1. 三层叙事结构

### 第一层（宏观）：晶圆级交换机的层级架构

这是在 Introduction 和 Background 里要讲的事。不是 LP 本身，是 LP 所嵌入的那个更大的结构：

```
Wafer-to-Wafer 拓扑
  └── Interposer-to-Substrate 层
        └── Die-to-Interposer 层
```

三个层级各有各的模型：
- **Die-Interposer 层**：UCIe + ubump + 交换 die crossbar。这是 bump 约束和 lane 分配的主战场。
- **Interposer-Substrate 层**：SerDes 全局链路 + C4 bump。布线资源和 substrate 拓扑在这里。
- **Wafer-Wafer 层**：多晶圆级联。当前模型不覆盖，作为扩展方向在 Discussion 中讨论。

**论文要讲清楚的事**：我们不是在一个平的空间里做 LP。LP 坐在三层物理架构中间，每一层都可以用自己的方式收紧约束。不同层之间的分工——哪层管信号、哪层管电源、哪层管全局带宽——本身就是设计决策。

当前论文草稿的 Intro 已经写了"两层 DSE 架构"（外层选型 + 内层 LP），但缺少**三层物理架构**的明确展开。Background 章需要补。

### 第二层（中观）：统一 LP 的对抗结构

这是 Overview 的核心。叙事逻辑：

1. **给定技术选型，剩下的事全部可以用一个变量表达：链路负载 L。**
2. **性能侧**：R 个最差流量模式打过来。对每个模式，路由变量决定每条边的负载。L 取所有模式的包络。
3. **物理侧**：L → 物理 lane 数 → 信号 bump + 动态功耗 → 电源 bump → 温度。全部是 L 的线性函数。
4. **对抗的交汇点**：L 既是性能侧的"至少需要"（$L_e \ge L_e^{(r)}$），又是物理侧的"最多能给的底线"（因为 L 推高了 bump 和热约束）。可行当且仅当存在 L 能同时满足两边。
5. **二分搜索**：固定 B 判可行，对数次 LP。

**这个故事的好处**：它不依赖任何特定假设。R 怎么选、路由怎么定、物理模型用什么精度——都是可替换的。框架的贡献在于**把对抗形式化了**，不在于任何一个具体的选择。

这部分的数学已经完整（MATH_MODEL_COMPLETE_V2.md），但论文草稿的 Overview 还在用旧版 `max L_e ≤ 1`。需要重写 `Tex/Overview/2_performance.tex` 和 `Tex/Overview/5_unified.tex`。

### 第三层（微观）：接口的可替换性

这是框架工程层面最重要的属性，应该在 Overview 末尾或 Sensitivity 开头明确讲：

1. **R 的选取是独立接口。** 群论归约是一种方法；暴力枚举是另一种；随机采样是第三种。论文的 R 是用群论给出的，但代码的 `AbstractTrafficPatternSelector` 不绑定任何一种。
2. **路由策略是独立接口。** Valiant 自适应路由是我们的默认选择，但最小路由、 oblivious routing、或其他 heuristic 可以换入。
3. **物理模型精度可调。** 每个约束族都有 L0（一条不等式）和 L1（完整线性不等式组）两级。MFIT 的热网络可以替换简单 RC 网络。

**代码里必须体现这个设计。** 每个接口是一个 ABC，换一个实现不影响其他模块。

## 5. 叙事上的注意事项

- **不要声称"我们的方法能处理所有拓扑"** — 明确说对称性假设是方法边界。
- **不要声称"无阻塞保证"** — 说"无阻塞潜能"，强调早筛定位。
- **R 的选取不是模型的一部分，是输入。** 群论归约是我们的选择，暴力枚举也是合法选择。
- **线性的意义要反复讲** — 不是因为"数学漂亮"，是因为"线性意味着对偶变量可以直接翻译成设计优先级"。这是体系结构人要的东西。
- **B 的二分搜索比 max B 优化更干净** — 不是因为"max B 有双线性"（那是技术困难），而是因为"二分搜索把判定和优化解耦，每次判定只有线性约束没有目标函数，更透明"。
