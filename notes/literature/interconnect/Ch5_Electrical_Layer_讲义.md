## 开篇：电气层是什么？

前面四章，我们一直在讲"数字层"——协议怎么打包、适配器怎么纠错、逻辑 PHY 怎么训练。这些逻辑的正确性建立在一个假设上：**物理信号能可靠地从 A 点传到 B 点。**

第五章就是定义这个假设的边界条件。它不是教你设计发送器电路——它告诉你：**如果你的通道满足这些电气参数，你的物理信号就是"合规的"，数字逻辑层的假设就是成立的。**

规范 p180 开篇列出了 8 条关键属性。我不逐条念，而是把它们按"体系结构者关心的维度"重新组织。

## 第一讲：两种电气世界

规范 p180 列出了这两种封装选项在电气层的根本差异。这些差异不是因为"Advanced 贵所以好"，而是因为**物理距离不同，电气需求自然不同**。

### 1.1 为什么发送器阻抗不同？

规范 p186, Table 5-3：

| | Advanced Package | Standard Package |
|---|---|---|
| 驱动器阻抗 | **22-28 Ω** | **27-33 Ω** |
| 接收端端接 | **无（unterminated）** | **有（terminated）** |

为什么 Advanced 的阻抗更低？

**因为 Advanced 走线极短（<2mm），信号的波长相对于走线长度很大——反射即使存在，也在极短时间内衰减，不会干扰下一个 bit 的采样。** 所以你可以用较低的驱动阻抗（驱动能力更强、信号上升更快），而且接收端不需要端接电阻来吸收反射——反射本身就不构成威胁。

Standard Package 走线长达 25mm。32 GT/s 下，1 UI = 31.25 ps。电信号在封装基板上的传播速度大约是 150 μm/ps → 25mm 需要约 167 ps ≈ **5.3 UI 的飞行时间**。反射从发送端到接收端再回来 = 10+ UI。如果接收端不端接，前一个 bit 的反射会和后面第 10+ 个 bit 混叠。**必须端接。**

**两个世界不是因为"一个高级一个低级"——是因为物理距离差了一个数量级，电气行为完全不一样。**

### 1.2 DC 耦合、单端信号 —— UCIe 为什么不用差分？

规范 p180：
> Single-ended unidirectional data signaling. DC coupled point-to-point interconnect.

PCIe 用差分信号（每 Lane 2 根线，P 和 N），UCIe 用单端（每 Lane 1 根线 + 地参考）。

差分信号的好处是抗共模噪声——在长距离 PCB 上，外部干扰会让两根线的电压同时上下浮动，但两线电压差（差分信号）保持不变。

封装内共模噪声极低——走线之间间距大（bump pitch 25-130μm）、走线极短、屏蔽好。单端就够了。**每 Lane 节省一根物理线——对于 x64 Module，省了 64 根线、64 个 bump。这对成本和边沿面积是巨大的节省。**

## 第二讲：通道规格 —— 怎样算"好的通道"？

规范 5.7 节（p199-201）定义了通道的电气边界。这是本章**最核心的部分**——它回答了：对于一个给定的封装设计，你的走线能不能用？

### 2.1 VTF（电压传输函数）方法

UCIe 不规定通道的具体物理参数（走线宽度、介质材料、层数），而是规定了一个**行为边界**：

> 在任何频率下（从 DC 到 Nyquist 频率 fN = 数据速率/2），你的通道损耗必须大于某个掩模线，串扰必须小于某个掩模线。

这意味着：你可以用任何材料（硅、有机、玻璃）、任何走线形状（微带线、带状线）——只要电气行为在掩模范围内。

### 2.2 损耗掩模

规范 p201, Table 5-11：

| 数据速率 | Advanced Package 损耗 | 标准 |
|---------|:---:|---|
| 4-16 GT/s | L(fN) > **-3 dB** | Nyquist 频率处损耗必须大于 -3dB |
| 24-32 GT/s | L(fN) > **-5 dB** | 高速时放宽到 -5dB |

**-3dB 意味着什么？** 信号到达接收端时，幅度至少是发送端的 70%（-3dB = 10^(-3/20) ≈ 0.71）。-5dB ≈ 56%。**高速时允许更多损耗——因为眼图更小，对损耗更敏感，但物理上高频衰减也更大，规范在"物理可行"和"信号可用"之间取了折中。**

**这里有一个重要的隐含约束**：损耗掩模是**线性**的——从 DC 到 fN 是一条直线。这意味着通道必须展示出**平滑的、可预测的频率响应**。任何在特定频率的"坑"（谐振、阻抗突变）都会导致掩模违规。**这对封装设计者来说，本质上是一道"必须让走线阻抗保持一致"的命令。**

### 2.3 串扰掩模

规范给了一个联合约束：

> XT(fN) < 1.5 × L(fN) - 21.5 (4-16 GT/s) 且 XT(fN) < -23 dB

串扰必须**低于**损耗的函数。这非常巧妙——如果一个通道损耗很大（信号很弱），那它对串扰就更敏感（串扰必须更低）。反之如果损耗很小，串扰可以稍微高一点。**通道损耗和串扰不是独立的——规范用一个联合约束把它们绑在一起。**

## 第三讲：Bump Map —— "物理对齐"的合同

规范 5.7.2.2-5.7.3.4 节（p201-233）用了约 33 页定义 Bump Map。这是规范里最"物理"的部分——它精确规定了每个信号的 bump 位置。

### 3.1 Bump Map 是做什么用的？

两个 Die 的 UCIe 接口需要物理对接。Die 0 的 Lane 3 TX bump 必须正好对准 Die 1 的 Lane 3 RX bump。如果两个 Die 来自不同厂商，它们**唯一的共同参考**就是 UCIe 规范定义的 Bump Map。

**Bump Map 是一个"互操作合同"——你按这个坐标放 bump，我按这个坐标放 bump，咱俩的 bump 就能对上。**

### 3.2 Dead Bug 视角

规范 p201：
> All bump matrices are defined with **"dead bug" view** — the viewer is looking directly at the UCIe micro bumps facing up, with the die flipped like a "dead bug".

"仰面朝天的死虫子"——芯片翻转，bump 朝上。这是物理对接最直观的视角。

### 3.3 模块命名规则 —— 为什么需要这么复杂？

规范 p219-233 花了大量篇幅定义模块命名（比如 "UCIe-A-1M-64L-10C-45P"）。这不是无意义的标签——**名字编码了物理尺寸和配置，让两个厂商能验证"我们的模块能对接"。**

命名约定拆解：
```
UCIe-A = Advanced Package (UCIe-A x32 = x32 Advanced Package)
1M = 1 Module
64L = 64 Lane
10C = 10 Column（bump 矩阵列数）
45P = 45 μm Pitch
+ 旋转方向（Standard Die Rotate / Mirrored Die Rotate）
```

**旋转方向是核心**：两个 Die 对接时，一个 Die 的 bump 矩阵相对于另一个可能需要旋转 180° 或镜像翻转。规范定义了完整的命名方案来覆盖所有可能的对接配置——包括不同数量 Module 之间的互操作。

### 3.4 单模块的物理尺寸

规范 Table 5-2（p184）给出了参考值：

| 封装 | 宽度/Module | 深度（45μm pitch, 10-column） |
|------|:---:|:---:|
| Advanced x64 | **388.8 μm** | ~1043 μm |
| Standard x16 | **571.5 μm** | ~1320 μm |

**对体系结构的意义**：如果你要在一块芯片的边沿放 4 个 Advanced x64 Module，你需要大约 4 × 389 μm ≈ **1.56 mm 的边沿长度**。在 5nm 节点，这个边沿可以放大约 1000 个标准单元行高——这是不小的物理面积。

Bump 间距从 45μm 到 25μm，深度也相应变化。**技术上你可以选更小 pitch 来减小面积，但规范按 pitch 分了 4 个 Group（Group 1: 25-30μm, Group 4: 45-55μm），更小 pitch 可能限制最高频率。这是密度和速率之间的经典取舍。**

## 第四讲：BER —— 两档误码率的体系结构含义

规范在 Table 1-1, 1-2 中定义了 BER 的分档。第五章 p236 讨论了 BER 和 CRC/Retry 的关系。

### 4.1 为什么分两档？

| 封装 | 低速 | 高速 |
|------|:---:|:---:|
| Advanced | 1e-27 (≤12 GT/s) | 1e-15 (≥16 GT/s) |
| Standard | 1e-27 (≤8 GT/s) | 1e-15 (≥12 GT/s) |

频率越高 → 信号衰减越大 → 眼图越小 → 噪声裕度越小 → 更容易出错。BER 的跳变不是一个"设计缺陷"，而是**物理定律的结果**。

Advanced Package 为什么可以同一 BER 到 12 GT/s 而 Standard 到 8 GT/s 就要降级？因为 Advanced 走线更短（2mm vs 25mm），更短意味着更少的高频衰减，更小的 ISI。

### 4.2 BER 1e-15 和 1e-27 在系统层面意味着什么？

**在 x64 @ 32 GT/s = 256 GB/s 单向链路上**：

```
BER = 1e-15：
  每秒传输 2.048 × 10^12 bit
  每秒平均错误：2.048 × 10^12 × 1e-15 = 2.048 × 10^-3 个 bit 错误
  平均约 500 秒（~8 分钟）一个 bit 错误

BER = 1e-27：
  每秒平均错误：2.048 × 10^12 × 1e-27 = 2.048 × 10^-15
  平均约 15,000,000 年一个 bit 错误
```

**1e-15 下每 8 分钟一个 bit 错误 → 适配器的 CRC 和 Retry 是必要的。1e-27 下基本上永远不会错 → 适配器的 CRC 理论上可以省，Retry 也可以省。** 规范没有强制省——因为"保险便宜"（CRC-16 的面积和功耗极低），但给了实现者这个选择。

### 4.3 体系结构的关键洞察

**BER 1e-15 看起来很低（一千万亿分之一），但在 256 GB/s 链路上仍然每 8 分钟一个错误。** 适配器的 Retry 机制就是为这个频率设计的——每 8 分钟来一次微小的重传停顿，对上层性能影响可以忽略（重传几十个 Flit = 几十纳秒）。

**但如果你有 1000 条这样的链路（大型 SiP），每秒就会有 2 个错误。这不是可以忽略的。** 适配器的重传机制在聚合层面是需要被建模的——虽然每条链路罕见，但大规模 Chiplet 系统的聚合错误频率可能成为可测量的性能开销。

## 第五讲：时钟和 Sideband 电气

### 5.1 时钟架构

规范 p181：REFCLK = 公共参考时钟，推荐 100 MHz。所有 Die 共享同一个时钟源。

对于体系结构，这意味着：**整个 SiP 的所有 UCIe 链路共享同一个 100 MHz 参考时钟。** 这简化了时钟域交叉（不需要异步 FIFO），但也意味着 REFCLK 是一个单点故障——如果 REFCLK 不稳定，所有链路同时受影响。

### 5.2 Sideband 电气

规范 5.13 节（p239-241）定义了 Sideband 的电气参数。Sideband 用 **800 MHz 固定时钟**，**单端数据**，**Always-On 电源域**。

Sideband 的低速率（800 MHz）使得它的电气要求远低于 Mainband。即使 Mainband 因为信号退化需要降速或 Retrain，Sideband 通常不受影响——因为 800 MHz 的信号远比 32 GHz 的信号容易传输。

**这是一种"带外管理"设计：Mainband 是你的数据面（快、可能出问题），Sideband 是你的控制面（慢、极其可靠）。即使数据面崩了，控制面还能工作——重建数据面靠控制面。**

## 全章总结：电气层就是"物理可能性的边界"

第五章不教你设计发送器。它给你的是**约束**：

| 约束 | 对你意味着什么 |
|------|-------------|
| 驱动器阻抗范围 | PHY 的面积和功耗受此约束 |
| VTF 损耗/串扰掩模 | 封装设计的边界——走线可以多长、材料可以怎么选 |
| Bump Map | 芯片边沿面积的硬约束——Module 宽度 × 数量 = 物理边沿需求 |
| BER 分档 | 适配器 Retry 的频率上限——决定了可靠性机制的需求 |
| REFCLK 100MHz | 全局时钟的单点故障风险 |
| Sideband 800MHz Always-On | 控制面的独立性——数据面崩了不影响恢复能力 |
