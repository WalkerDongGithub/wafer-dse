# 反射的后果 —— 谁受害了？

---

## 1. 单一突变点：能量分流

传输线在 $x = 0$ 处从 $Z_{01}$ 变到 $Z_{02}$。入射波 $V_+$ 从左边来。

交界面处：

$$V_- = V_+ \cdot \frac{Z_{02} - Z_{01}}{Z_{02} + Z_{01}}, \quad V_T = V_+ \cdot \frac{2Z_{02}}{Z_{02} + Z_{01}}$$

**发生了什么**：入射波的一部分 $|V_-|/|V_+| = |\Gamma|$ 弹回左边，剩下 $|V_T|/|V_+| = 1 + \Gamma$ 继续往前走。

**谁受害了**：**接收端**。本来 $V_+$ 全部应该到达接收端的——现在只有 $V_T$ 过去了。剩下的能量在交界面处被弹回了发送端方向。**接收端收到的信号幅度减小了。**

---

## 2. 但这个幅度减小对数字信号意味着什么先不说——更严重的事在后面

假设发送端阻抗 $Z_S \neq Z_{01}$（也不匹配）。

步骤 1：入射波 $V_+$ 到达交界面 → 反射波 $V_-$ 弹回发送端。
步骤 2：$V_-$ 到达发送端。发送端阻抗 $Z_S \neq Z_{01}$ → 再次反射（反射系数 $(Z_S - Z_{01})/(Z_S + Z_{01})$）→ 一个二次波向接收端跑。
步骤 3：二次波到达接收端。叠加在原始信号上。
步骤 4：如果接收端也不匹配 → 又来一次反射 → 来回往复。

**每一步都在接收端产生一个新的"影子信号"。**

```
接收端看到的电压：

  t = TD:          原始信号到达
  t = 3·TD:        第一次反射的"影子"到达（走了发送端→接收端→发送端→接收端）
  t = 5·TD:        第二次反射的"影子"到达
  ...
```

**这串影子信号就是 ringing。它在接收端电压上创建了多个台阶——不是在"1"和"0"之间干净切换，而是在中间振荡。** 每一个台阶都让后一个 bit 的起始电平发生了偏移。

---

## 3. 反射的真正受害者：后续比特

一个 bit 的反射波在线上来回弹了 10 个 UI 才衰减掉。第 $n$ 个 bit 在 $t_n$ 时刻被采样。此时线上还在回荡的反射波来自：

- 第 $(n-1)$ 个 bit（刚刚过去）
- 第 $(n-2)$ 个 bit（还在蹦）
- 第 $(n-3)$ 个 bit（快衰减完了但尾巴还在）

**接收端在采样第 $n$ 个 bit 时看到的电压不是"这个 bit 应该有的电压"，而是"这个 bit + 前几个 bit 还在蹦的影子"的总和。** 一个之前的 bit 是 1，让线上电压偏高，下一个 bit 是 0，采样时的电压比真正的 0 高了一截——可能被误判为 1。

**这就是 ISI（码间干扰）。反射造成的 ISI 是数字通信的灾难。**

---

## 4. 谁的锅？

**发送端不受伤。** 发送端只是看到反射波回来了——它不误读数据（它不负责接收）。反射波的能量在发送端阻抗上被部分吸收或再次反射。

**接收端受伤。** 接收端需要判断每个 bit 是 0 还是 1。反射波产生的电压偏移直接降低这个判断的准确性——**眼图缩小**。

**经过突变点之后的透射波自己也受害。** 透射波幅度只有 $(1+\Gamma)V_+$。如果 $\Gamma$ 大，透射波留下的能量少，接收端收到的信号弱——和噪声相比，信噪比下降。

---

## 5. 回到 UCIe 的两种端接策略 — 解释变了

### Advanced Package — 无接收端端接

发送端驱动阻抗 22–28 Ω ≈ $Z_0$。发送端匹配。

- 入射波进入线，幅度 = $V_S/2$（阻抗分压）
- 到达接收端。接收端开路（CMOS 输入电容 ≈ 2 pF，高频下接近开路）→ $\Gamma_L \approx +1$ → 全反射
- 反射波回到发送端。发送端匹配（22–28 Ω ≈ $Z_0$）→ $\Gamma_S \approx 0$ → **发送端吸收了这个反射——它不弹回去**
- 线长 2mm → 来回 26 ps < 1 UI（31.25 ps @ 32 GT/s）→ **在同一个 UI 内，发送端就处理完了反射**

**接收端受到的唯一影响是它在反射来的时候电压短暂加倍（开路端电压加倍）——这对 CMOS 接收器来说是好事，因为加倍后的电压更快越过阈值。**

### Standard Package — 必须接收端端接

和上面一样的逻辑，但线长 25mm → 来回 334 ps ≈ 10 UI。

如果接收端不端接 → 反射波跑了 10 个 UI 才回到发送端。在这 10 个 UI 期间，发送端已经把后面 9 个 bit 推进去了。**反射波回来的时候，它叠加在第 11 个 bit 上，而不是第一个 bit 上。**

**所以接收端必须匹配——在接收端一次性吸收信号，不让反射发生。** 否则反射波在线上的来回时间（10 UI）远超过一个 bit 的时间（1 UI），它会跨越多个 bit、污染整个比特流。

---

## 6. 总结 — 谁受害？

```
单一反射（开路/短路/不匹配接头）：

  ├── 接收端信号幅度减小（部分能量被弹回）
  └── 不直接影响发送端

多次反射（两端都不匹配 → 来回弹）：

  ├── 接收端电压上叠加多个"影子" → 眼图缩小 → BER 升高
  └── 发送端看到异常阻抗——但不误读数据

UCIe 的做法：

  Advanced（短距）：
    接收端可以不匹配 → 反射发生 → 但发送端匹配吸收 → 反射波被快速处理
    → 且信号来回 < 1 UI → 不影响后续比特

  Standard（长距）：
    接收端必须匹配 → 反射不发生 → 信号在接收端一次性被吸收
    → 防止反射波在长线上跨越多比特
```
