# 对标与复现实验计划 (Benchmark & Replication Plan)

**目标**: 通过复现同领域（Chiplet DSE）标杆工具/方法，在统一的参数集下进行对比，验证我们的 DSE 框架作为“早筛模型”的有效性与价值。

**核心思路**:
1.  **方向一**: 先定义我们的“基准可行集”（Our Ground Truth）。在选定的物理/性能参数下，用我们的框架跑一遍，生成一个“判定矩阵”（哪些组合被我们筛掉，哪些留在我们的早筛范围内）。这是后续所有对比的基石。
2.  **方向二**: 复现对标物的“判定逻辑”。选择一到两个代表性的 Chiplet DSE 工作，复现其核心判定逻辑（非全部功能），使其能在我们的参数集上输出它的“可行集”。

最终，我们将用这两个集合进行对比，量化展示我们的“早筛”价值：我们的筛除率（排除集大小）是否显著高于对方？我们筛掉的方案，对方是否判定为可行？我们筛留的方案，对方是否也判定为可行？

---

## 方向一：敲定基准可行集 (Our Baseline)

**任务**: 确立我们的 DSE 框架在实验中始终使用的参数集，并运行生成“判定矩阵”。

### 1. 参数集设计 (Parameter Set Design)

我们需要设计一套能覆盖典型 Chiplet 设计空间的参数组合。这将是我们对比实验的输入。

*   **拓扑参数**:
    *   类型: Mesh, Torus, Dragonfly (主流 NoC 拓扑)
    *   规模: 4x4, 8x8 (从小到大，覆盖不同 Die 数量)
*   **物理参数 (引用 `config/params/`)**:
    *   μbump 间距: 45μm (先进封装), 130μm (传统封装)
    *   散热能力: 标准 (R_vert=1.5 K/W), 受限 (R_vert=2.5 K/W)
    *   制程节点: 通过 `ucie-32g.yaml` (32G SerDes), `trad-air-112g.yaml` (112G SerDes) 体现。
*   **性能参数**:
    *   无阻塞约束: 开启（我们的核心约束）

### 2. 基准运行 (Baseline Run)

使用我们的框架 (`src/problem/builder/` + 查询逻辑) 在上述参数集上进行全组合运行。

*   **产出**: `benchmark/results/our_baseline_matrix.csv`
    *   **列**: 拓扑, 规模, μbump, 散热, 制程, 我们的判定 (可行/不可行), 触发的约束（若不可行）
    *   **意义**: 这份矩阵是我们的“审判标准”，后续所有对标都将以此为参照。

---

## 方向二：复现对标方案 (Replication Plan)

**任务**: 选择标杆 DSE 工具/方法，以最简方式复现其核心判定逻辑。

### 1. 对标物选择 (Target Selection)

*   **标准**:
    *   专注于 Chiplet 设计空间探索（DSE）。
    *   开源，或算法描述详尽可复现。
    *   核心逻辑包含“可行/不可行”的判定（即使是隐式的）。
*   **初步候选**:
    *   **RapidChiplet (ICCAD'21)**: 经典的 Chiplet DSE 框架，探索封装技术与网络拓扑的协同。
    *   **ChipletOpen**: 开源的 Chiplet 设计工具集。
    *   **其他**: 在 `notes/literature/dse_methodology/` 中的论文。

### 2. 最简复现策略 (Minimal Replication Strategy)

我们的目标不是全量复现对标物，而是复现其**核心判定逻辑**，使其能在我们的参数集上给出它的“可行集”判定。

*   **步骤**:
    1.  **解构**: 分析所选对标物的方法论，确定其核心的“可行性判定”是如何进行的。
        *   它考虑了哪些约束？（物理？性能？）
        *   它的判定标准是什么？（例如：仅考虑功耗预算，不考虑 μbump 密度；或假设网络是固定的 CLOS 拓扑）
    2.  **实现**: 编写一个 Python 脚本 `benchmark/replication/<target_name>_checker.py`。
        *   **输入**: 与我们的基准运行完全相同的参数集。
        *   **输出**: 对标物的判定结果（可行/不可行）。
        *   **核心**: 用 Python 逻辑（无需 LP 求解器，除非必要）快速复现其判定规则。
    3.  **验证**: 用对标论文中公开的测试用例验证我们的复现脚本是否正确。

### 3. 对比与分析 (Comparison & Analysis)

一旦基准矩阵和对标判定脚本都准备就绪，我们将进行正式的对比。

*   **脚本**: `benchmark/compare_with_baseline.py`
*   **动作**: 将对标判定结果与我们的基准矩阵进行合并。
*   **产出**: `benchmark/reports/comparison_analysis.md`
    *   **核心分析**:
        *   **我们的筛除率**: 我们筛掉的组合占比 vs 对标物筛掉的占比。
        *   **差异案例**:
            *   **Case 1（我们筛掉，对标保留）**: 标注出来。我们需要解释：我们为什么筛掉（我们的哪条约束起作用了？），对标为什么保留（它的约束是什么样的？）。这是我们论文的核心素材！
            *   **Case 2（我们保留，对标筛掉）**: 标注出来。我们需要反思：是我们的筛除逻辑太松了吗？还是对标物漏判了？
        *   **结论**: 用数据论证我们的“早筛模型”比传统方法更严谨、更贴合物理真实。
