# Q&A 协作文件格式规范

本规范定义 meeting 的 **Q&A 阶段**中，agent 之间收发请求/质疑文件的**固定格式**。

目标：**询问要精准**（可定位、可回答），**回复要有据可循**（像 rebuttal 回复信一样逐条回应、附证据）。

## 文件流转与命名

- **询问**：询问者把文件写到**被询问者**目录 `memory/<被询问者id>/` 下。
- **回复**：被询问者处理后，把回复写到**询问者**目录 `memory/<询问者id>/` 下。
- 命名约定（从文件名即可看出"谁发给谁、关于什么"）：
  - 询问文件：`ask-<询问者id>-<主题>.md`
  - 回复文件：`answer-<被询问者id>-<主题>.md`（主题与对应询问一致）

例：`01-code-engineer` 向 `02-code-reviewer` 询问某个物理参数出处 →
`memory/02-code-reviewer/ask-01-code-engineer-热参数出处.md`
`memory/01-code-engineer/answer-02-code-reviewer-热参数出处.md`

## 询问格式（要精准）

```markdown
# Ask from <询问者id> to <被询问者id>

- **主题**：一句话说明要问什么。
- **背景**：为什么需要问（我缺什么信息、卡在哪一步）。1~3 句即可。
- **问题列表**（每条独立编号，标阻塞/非阻塞）：

  - **Q1（阻塞）**：具体问题——精准到某个文件/数字/公式/接口/某句话。
  - **Q2（非阻塞）**：具体问题。

- **期望**：希望对方给什么（数值 / 出处 / 修改建议 / 确认或否定）。
- **截止**（可选）：本次 meeting 内 / 下次 meeting 前。
```

### 询问的精准原则

- 每条问题必须**可定位、可回答**：落到具体对象（哪个文件、哪个数字、哪个公式、哪个接口、哪句话），不要泛问"你觉得这个对不对"。
- 标出**阻塞 / 非阻塞**：阻塞 = 不回答就没法继续 do；非阻塞 = 只是求证或优化。
- 一次问清楚，不挤牙膏；但也别一次塞几十个问题。

## 回复格式（要有据可循）

像 rebuttal 回复信一样，**逐条对应询问编号**：

```markdown
# Answer from <被询问者id> to <询问者id>

- **Q1**：
  - 结论：已解决 / 部分解决 / 无法解决（附原因）。
  - 依据：可复现的证据——文档原文、文件+行号、Python 验算结果、标准文档条目之一。
  - 若需改动：说明改动点与位置。

- **Q2**：
  - ...

- **遗留问题**：哪些问题本次未解决、为什么、建议怎么推进。
```

### 回复的"有据可循"原则

- **不能只给结论、不给证据**。每条回复都要附依据：文档原文 / 代码位置 / Python 验算结果 / 标准出处，至少其一。
- 涉及数值的，用 Python 验算并贴结果，不要口头说"是对的"。
- 拿不准就明确说"待核实 + 建议谁去查"，不要硬答。
- 与询问编号一一对应，方便 03a 汇总时追踪"谁的问题、被谁、如何解决"。
