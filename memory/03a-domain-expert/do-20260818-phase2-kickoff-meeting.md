# wafer-dse 第二阶段核心方向与验证逻辑会议总结

**日期**: 2026-08-18
**会议主题**: 确立项目核心定位、验证逻辑与对标策略
**结论**: 确立了以“双高筛选”为核心的 DSE 框架定位，并明确了如何通过对比实验验证其价值。

## 一、 核心定位：行业最严苛的“双高筛选器”

我们的 DSE 框架不是一个优化器，而是一个极高标准的**可行性筛选器**。我们的价值在于通过“双重漏斗”，将设计空间收紧到“能造且能用”的极小可行子集。

### 1. 双重筛选漏斗（核心护城河 — 早筛模型）

**关键提醒：我们的模型是「早筛模型」，不是「早选模型」！我们的核心动作是“筛除一定不行的点”，而非“选出一定行的点”。**

*   **第一漏斗（物理筛选）：工业级物理约束**
    *   **约束**: 基于真实工业工艺的 μbump 密度、电流、散热热阻、功耗（取自 `ucie-32g.yaml` 等）。
    *   **动作**: **筛除** 所有“物理上做不出来”的设计（例如，μbump 预算不足）。我们不保证剩下的都能造，但保证被筛掉的一定造不出来。
*   **第二漏斗（性能筛选）：理论级无阻塞约束**
    *   **约束**: 基于 Valiant 路由的全排列无阻塞包络（已在 `_envelope.py` 中实现）。
    *   **动作**: **筛除** 所有“必然会阻塞”的流量模式。我们不保证剩下的模式在任何情况下都绝对无阻塞，但保证被筛掉的模式在该拓扑下必定是阻塞的。

### 2. 对比逻辑与评估标准

我们的评估标准与其他研究相反：**筛除率越高（留下的集合越小），模型的早筛价值越大，但前提是必须“筛得准”。**

*   **传统模型**: 为了追求高吞吐量/低延迟，容忍巨大的 Buffer 和阻塞，或在乐观假设下给出大而全的可行集。它们是“早选模型”，试图给出最优解，但容易给出假阳性。
*   **我们的模型**: 给出的是一个**“绝对排除集”**——任何不在这个集合里的设计，都可以被判定为“物理上不可行”或“性能上必然阻塞”。这为设计师节省了海量的试错成本。

**四种对比结果的处理**:
| 他人判断 | 我们判断 | 含义 | 结论 |
| :--- | :--- | :--- | :--- |
| 可行 | 可行 | 一致 | 无分歧 |
| 可行 | **不可行** | **关键分歧** | ⭐ **核心价值点**：我们能指出“对方漏掉了哪条物理或性能约束”，证明他们的方案是伪优解。 |
| 不可行 | 不可行 | 一致 | 无分歧 |
| 不可行 | **可行** | **危险信号** | ⚠️ 说明我们漏了约束，需警惕。 |

### 3. 论文核心卖点（暂定）

> **早筛模型核心声明**：本 DSE 框架是首个在 LP 层面同时实现 **“工业级物理约束”+“理论级无阻塞约束”** 的**设计空间早筛工具**。它的核心价值不是提供“最优解”，而是提供一个“绝对排除集”——精准识别并排除现有文献中基于乐观假设的、物理上不可行或性能上必然阻塞的伪优解，从而将设计空间从无限大收紧到一个极小的、值得深入研究的边界地带。

## 二、 对标策略：找对敌人，用对数据

*   **废弃**: Cerebras WSE（整晶圆路线不同，我们的方法无法模拟其封装，仅可对标部分功耗数据）。
*   **确立**: **UIUC** 和 **清华大学**的同路线（chiplet 互连）论文作为核心对标。
*   **方法**: **优先使用论文原文公开数据**，不额外复现对方代码。将精力集中在验证我们自己的框架上。

---

## 三、 下一步验证计划：证明“早筛”的价值

为了验证我们作为“早筛模型”的核心价值，我们将进行以下实验：

1.  **核心实验：伪方案筛除验证（我们的主战场）**
    *   **动作**: 将对标论文（UIUC/清华）中的“声称可行”的架构参数，跑入我们的 DSE 框架。
    *   **预期**: 他们的方案会被我们的“早筛”逻辑判定为**“不可行”**或**“必然阻塞”**，触发“关键分歧”情况。
    *   **产出**: 一份详细的“排除清单”，逐条列出“他人认为可行→我们判定必然失败”的案例，并精确定位是哪一条物理约束（如 μbump）或性能约束（必然阻塞）导致的失败。这就是我们模型的核心产出价值。

2.  **补充实验：一致性验证（防守）**
    *   **动作**: 用我们的框架复现对标论文中已被证明的“不可行”案例。
    *   **预期**: 双方均判断为不可行，证明我们的筛除逻辑具备基本可信度，不会“乱杀”。
