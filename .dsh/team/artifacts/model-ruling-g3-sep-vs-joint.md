# 模型层裁决：G3 分离 vs 联合等价性（insight 4）

> DomainExpert 模型层裁决，2026-08-20。来源：DataSteward 数据报告 `data-report-e1-e5-e6-ec.md` G3 节 + EvalDesigner 实验设计 E3B。

## 一、事实与数学分析（接受 DataSteward 发现）

当前已实现子集（C1 μbump + die 级热 + 包络 + die 缩放 + B\* 二分）下：
1. 所有物理约束对 B 线性（bump/热均 ∝ B·L），可行性边界处 L 钉在包络 L\*（L ≥ L\* 为唯一性能约束，L 增大只会收紧物理约束 → 最优点 L=L\*）；
2. 几何面积 α_d=β_P=0 不随 B 变 → 恒松；
3. 因此 B\*_joint = min(B\*_bump, B\*_therm) 精确成立（可解析推导，实测 11/11 拓扑 rel_diff=0 证实）。

**判定：这是模型的诚实边界，不是 bug，不是数据错误。**"分离=联合"是当前线性可分离子集的数学性质，值得写进论文作为诚实的边界声明（审稿人会感谢这种诚实），而非掩盖。

## 七、v5.21 二分前提保险检查（DataSteward 提出，DomainExpert 定案，2026-08-20）

**背景**：v1 时代"低 B 恒可行"依赖 α=β=0 几何恒松；v5.21 面积上界 (2f)/布线 (2d) 进入主模型后，可行性对 B 的单调性（V5 §5.3 二分前提）需重新验证——若出现"可行性带"（低 B 不可行而中 B 可行），BmaxQuery 二分语义改变（找可行带下沿而非最大可行 B）。

**理论预期（DomainExpert）**：低 B 侧仍恒可行，单调性大概率保持——
1. 布线 (2d)：$\boldsymbol{\ell} = (S^{\text{bw}})^{-1}(B\mathbf{L})$，B→0 时 lane 数→0，布线容量约束松（容量 C>0 时恒可行）；
2. 面积 (2f)：$A_{\text{die}}(B) = d(B)^2$，B→0 时 $A_{\text{die}}(0) = d_0^2$——若 $d_0^2 \le A_{\max}$ 则低 B 可行；**若 $d_0^2 > A_{\max}$ 则为"全 B 不可行"的静态构型淘汰**（不是可行性带，FeasibilityQuery 自然返回不可行）；
3. α_d>0 时面积给出闭式上界 $B \le (\sqrt{A_{\max}} - d_0)/\alpha_d$——上界约束，不影响低 B 侧。

**处理约定**：
- **执行**：DataSteward 在新模型下先做单调性抽查（沿用 run_monotonicity 模式，B 网格含低 B 段），通过后再跑 C3'/C4'/C5'；
- **预期结果**：可行性集为 [0, B_max] 区间（单调成立）→ BmaxQuery 语义不变，二分照常；
- **若实测出现真可行性带**（低 B 不可行、中 B 可行）：**上报 DomainExpert 裁决**（BmaxQuery 语义调整或参数域限定），不自行改判；
- **若全 B 不可行**：构型静态淘汰（d_0² > A_max），照常报告；
- **二分上界建议**：α_d>0 时以面积闭式上界 $(\sqrt{A_{\max}}-d_0)/\alpha_d$ 为二分上界（加速 + 语义清晰），默认 α_d=0 档维持现状。

## 八、E3B v2 实测裁决（2026-08-20，DataSteward 27 组合 ucie-32g，α_d∈{0,0.001,0.01}）

**DomainExpert 裁决：C3' 当前不通过不构成限缩依据——是实现口径问题，不是数学事实。**
1. **根因**：v1 等价性是数学事实（约束对 B 线性 + L 钉包络；bump/热因素内部无优化自由度）。v2 的**布线因素有优化自由度（lane 布线决策 x_D2D）**：联合模型在候选路径中优化 x_D2D 满足 lane 需求；而分离决策基线的正当规格是**"固定候选路径"**（各因素独立判定、不共享/不借用联合优化自由度——这是"分离决策"的语义本身）。DataSteward 当前实现保留路径优化 = 分离基线偷用了联合模型的自由度 → 等价性平凡成立。
2. **行动**：CodeEngineer 在 src 支持"固定候选路径"分离布线判定（独立于联合模型的 x_D2D 优化）；DataSteward 重跑 C3'。
3. **固定路径须公平**（防审稿人"不公平基线"攻击）：用合理独立方案（如最短路径、或由拓扑决定的固定布线方案），不得刻意劣化——分歧应反映"分离决策不做跨因素联合优化"的代价，而非基线缺陷。
4. **结果处理**：重跑后 C3' 通过 → 主张成立（§5.4 双阶段定稿：v1 等价性边界 + v2 分歧）；仍不通过 → 才限缩（当前参数域分离=联合为数学事实，主张回到"单一模型统一求解"叙事）。v1 等价性边界（附录）与 C4' 绑定证据无论结果如何均保留。
5. **同步**：paper-skeleton §5.4 双阶段叙事维持（v2 待定），experiment-design E3B v2 状态由 EvalDesigner 标注（C4' ✅ / C3' 待固定路径重跑）。

## 十一、G7 power/GND 走线项模型式拍板（2026-08-21，作者 round 21+ 指令【1】E7 前置）

**背景**：作者标准耦合案例（INSIGHT_READING §4）——Power/GND 走线占用 RDL 容量，power 走线需求过大顶满布线容量 → (a) 提高散热 或 (b) 降性能。V5 v5.21 声明"power/gnd 与信号走线共享 RDL"但实现（WiringModel）只路由信号 lane（`Σ (B/lr)·L ≤ cap`）——**power 走线项是规范未实现缺口（G7）**，E7 阻塞。

**模型式拍板（edge/vert 容量，power 走线作为 rhs 扣减项共享容量）**：

$$ \sum_{\text{路径经过 } e} \frac{B}{\text{lr}_l} L_l + c_{\text{pwr}} \cdot P_{\text{die}}(B) \le \text{cap}_e $$

- $P_{\text{die}}(B) = P_0 + \beta_P B + P_{\text{dyn}}$（与热方程 (2c) 同源，die 级功耗）；
- $c_{\text{pwr}}$ = power 走线的"lane 当量"系数（单位功耗折算成 RDL 容量占用，W→lane 当量；参数 YAML 配置，含 power/gnd 走线宽度/电流密度折算）；
- **耦合机制**：β_P>0 时 $P_{\text{die}}(B)$ 随 B 增长 → power 走线占用同步增长 → 顶满 RDL → 必须 (a) 提散热（R_vert↓ 松热约束）或 (b) 降 B（降 power 需求）——"功耗—散热—布线/性能"三方牵制数学成立；
- **LP 保持**：固定 B 下 $P_{\text{die}}(B)$ 为常数 → rhs 扣减项，约束仍线性（LP 结构不变，insight 7 不受影响）；
- **C4 pad 容量**同理加 power 项（可选，E7 小实验先做 edge/vert）；
- 分离决策基线：power 走线作为**独立固定开销**判定（忽略与信号 lane 共享）→ 与联合模型分歧 = 耦合价值（D4 判据）。

**实现/执行**：CodeEngineer 小改（WiringModel 加 `power_trace` 参数，rhs 扣减 $c_{\text{pwr}} P_{\text{die}}(B)$）→ DataSteward 跑 E7 小规模（coupling_<params>.csv，冷却 4 档 × B_target 2-3 档）→ D1-D4 方向级判据。验证阶段策略【0】：小实现、小实验、方向验证。

## 十三、E7 变量表口径定案：power 耦合演示域（2026-08-21，DataSteward 域复核 + DomainExpert 裁决）

**复核发现（DataSteward，数据说话）**：β_P>0 时 power 项不显现——β_P 同时进 C_peak（thermal/bump 含 β_P·B）先把 B\* 压到布线余量充足处（B=295 时 power 扣减仅 ~69 lanes vs 边容量 2400），c_pwr 0↔2 零效应。

**机制分析（DomainExpert）**：β_P 是共享参数，进热/bump 的效果（压低 B\*）强于进 power 走线 rhs 的效果；B\* 被压低后 power 扣减随之变小，布线不绑定 → power 效应藏匿。

**变量表口径定案**：**power 耦合演示域 = 布线饱和（lanes 小 50-100）+ β_P 小/0**——避免 β_P 放大藏匿 power 效应。已出数据（β=0 + lanes=50 + c_pwr 试点）：c_pwr 0→2→10 → B\* 685→490→295；降功耗 c_pwr 2→0.5 → +40%；散热 R_vert 零释放（被 power 布线顶住）——完整三方牵制演示。

**论文口径（两证据 + 边界）**：
1. power 走线耦合（布线饱和域，β_P 小/0）：c_pwr 耦合 + 降功耗解锁 + 散热零释放——作者案例直接证据；
2. β_P>0 时 C_peak 主导（热/功耗先绑定）——"功耗增长被热约束吸收，未达布线域"边界观察；
3. **耦合域如实界定（D4 Conservative）**：不是所有参数域展示 power 耦合，耦合域 = 布线饱和 + β_P 小——数据说话，不夸大。

**执行**：DataSteward 按定稿口径重排 coupling CSV（演示域 β_P=0/小 + lanes 50-100）；EvalDesigner E7 变量表同步（β_P 档改小/0）。
